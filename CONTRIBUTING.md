# Contributing

Pull requests are welcome. Every pull request is reviewed before it merges — no exceptions.

## Ground rules

The [operating rules](https://github.com/abdeen-labs) apply to contributions:

1. One pull request, one task. A change that needs a second mission becomes a second pull request.
2. Boundaries hold. A change that alters a tool's storage, network egress, or telemetry must restate the boundary on the product page — and will be examined hardest.
3. Output is verifiable. State what the change does and how you verified it. Tests, recordings, and before/after evidence shorten review.

## Process

1. For anything larger than a small fix, open an issue first and state the task.
2. Fork, branch, make the change.
3. Open the pull request against `main`. Describe the task, the change, and the verification.
4. Review follows. Expect questions about scope and boundaries; expect requested changes.
5. A maintainer merges after review passes. Nothing merges unreviewed.

Repositories still marked private are pending release review. Contributions begin when a repository opens.
